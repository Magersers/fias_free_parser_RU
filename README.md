# 🏠 FIAS Free Parser RU

Красивый и практичный Python-скрипт для массового обогащения Excel-файла с ФИАС/GUID-идентификаторами адресов. Проект читает `input.xlsx`, обращается к публичному API AHunter, раскладывает адрес на структурированные поля и сохраняет удобный Excel-отчёт `output_addresses.xlsx`.

## ✨ Что умеет проект

- 📥 Читает входной Excel-файл `input.xlsx`.
- 🔎 Берёт ФИАС/GUID из первой колонки и дату из второй.
- 🌐 Запрашивает адресные данные через AHunter API.
- 🧩 Разбирает ответ на отдельные компоненты адреса:
  - регион;
  - район;
  - город;
  - населённый пункт;
  - улицу;
  - дом, корпус, строение, квартиру;
  - индекс;
  - часовой пояс;
  - данные почтового отделения.
- 💾 Кэширует ответы в `ahunter_cache.json`, чтобы не запрашивать один и тот же GUID повторно.
- 🛡️ Повторяет запросы при временных ошибках.
- 📊 Формирует аккуратный Excel-отчёт с фильтрами, закреплённой шапкой и настроенной шириной колонок.

---

## 📦 Структура проекта

```text
.
├── input.xlsx              # Входной файл с ФИАС/GUID
├── start.py                # Основной скрипт обработки
├── ahunter_cache.json      # Кэш API-ответов, создаётся автоматически
└── output_addresses.xlsx   # Итоговый отчёт, создаётся автоматически
```

> `ahunter_cache.json` и `output_addresses.xlsx` появляются после запуска скрипта.

## 🚀 Быстрый старт

### 1. Установите Python

Рекомендуется использовать **Python 3.9+**.

Проверьте версию:

```bash
python --version
```

### 2. Создайте виртуальное окружение

```bash
python -m venv .venv
```

Активируйте его:

#### Windows

```bash
.venv\Scripts\activate
```

#### macOS / Linux

```bash
source .venv/bin/activate
```

### 3. Установите зависимости

```bash
pip install requests openpyxl tqdm
```

### 4. Подготовьте `input.xlsx`

Файл должен лежать в корне проекта и называться именно:

```text
input.xlsx
```

Ожидаемый формат:

| Колонка | Что должно быть внутри |
|---|---|
| A | ФИАС/GUID адреса |
| B | Дата или любое дополнительное значение даты |

По умолчанию скрипт считает, что первая строка — это заголовки, а данные начинаются со второй строки.

## 📤 Результат

После запуска появится файл:

```text
output_addresses.xlsx
```

В нём будут следующие группы данных:

### 🏷️ Служебные поля

- `source_row` — номер строки во входном файле;
- `status` — результат обработки: `ok`, `not_found` или `error`;
- `error` — текст ошибки, если она возникла;
- `raw_json` — исходный JSON-ответ API;
- `input_fias` — исходный GUID;
- `date` — значение даты из входного файла.

### 🏡 Адресные поля

- `full_address` — полный красивый адрес;
- `postal_code` — индекс;
- `country_code`, `country_name`, `country_sign` — страна;
- `region`, `district`, `city`, `place`, `street` — основные части адреса;
- `house`, `building`, `structure`, `flat` — дом и детализация;
- `timezone`, `timezone_utc`, `timezone_msk` — часовой пояс;
- `post_office_address`, `post_office_lat`, `post_office_lon` — ближайшее почтовое отделение.

## ⚙️ Настройки

Основные параметры находятся в начале `start.py`:

```python
INPUT_FILE = "input.xlsx"
OUTPUT_FILE = "output_addresses.xlsx"
CACHE_FILE = "ahunter_cache.json"
START_ROW = 2
REQUEST_DELAY = 0.1
MAX_RETRIES = 3
```

| Параметр | Назначение |
|---|---|
| `INPUT_FILE` | Имя входного Excel-файла |
| `OUTPUT_FILE` | Имя итогового Excel-файла |
| `CACHE_FILE` | Файл кэша API-ответов |
| `START_ROW` | Строка, с которой начинается чтение данных |
| `REQUEST_DELAY` | Пауза между запросами к API |
| `MAX_RETRIES` | Количество повторных попыток при ошибке |

Если во входном файле **нет строки заголовков**, измените:

```python
START_ROW = 1
```

## 🧠 Как работает кэш

Скрипт сохраняет ответы AHunter в `ahunter_cache.json`.

Это полезно, потому что:

- повторный запуск проходит быстрее;
- одинаковые GUID не запрашиваются повторно;
- меньше нагрузка на внешний API;
- можно безопасно продолжить работу после сбоя.

Если нужно получить свежие данные заново — удалите `ahunter_cache.json` перед запуском.

## 🛠️ Возможные проблемы

### `ModuleNotFoundError: No module named 'requests'`

Установите зависимости:

```bash
pip install requests openpyxl tqdm
```

### `FileNotFoundError: input.xlsx`

Проверьте, что файл `input.xlsx` находится в корне проекта рядом со `start.py`.

### В отчёте статус `not_found`

API вернул ответ без поля полного адреса. Проверьте корректность ФИАС/GUID во входном файле.

### В отчёте статус `error`

Запрос завершился ошибкой. Текст причины будет в колонке `error`.

## ✅ Рекомендации для больших файлов

Для больших таблиц, например на несколько тысяч строк:

- не ставьте `REQUEST_DELAY = 0`, чтобы не перегружать API;
- не удаляйте `ahunter_cache.json` между запусками;
- периодически сохраняйте исходный `input.xlsx` отдельно;
- проверяйте колонку `status` после обработки.
